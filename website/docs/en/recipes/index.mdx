## The three keys

Every recipe is the same three moves in the same order.

<table className="ld-keytable">
<thead><tr><th>Key</th><th>What it decides</th></tr></thead>
<tbody>
<tr><td><Keys>b</Keys></td><td><strong>Where to look.</strong> A group, a subgroup tree, a project, or nothing at all when the answer is instance-wide</td></tr>
<tr><td><Keys>f</Keys></td><td><strong>What to keep.</strong> State, draft, labels, authors, approvals, dates</td></tr>
<tr><td><Keys>P</Keys></td><td><strong>How to keep it.</strong> The result becomes a tab, and it is still there tomorrow</td></tr>
</tbody>
</table>

Each recipe names the scope for <Keys>b</Keys>, the filter for <Keys>f</Keys>, and the tab name for <Keys>P</Keys>.

## Filter values

Label names, usernames, branch names and project paths complete from your own instance as you type, so a recipe never depends on you spelling a value from memory. A value that does not exist cannot be submitted, and an empty result restates the query that produced it. See [Filtering](/features/filtering).
